# Kenga Engine — План до коммерческого релиза и первой игры

> PROJECT_RULES.md строго. Цель: движок готов к коммерческому использованию для AAA-проектов и одна полноценная игра на движке.

---

## Часть A. Критерии «коммерческий релиз» движка

### A.1. Определение готовности

Движок считается готовым к коммерческому использованию для создания AAA-игр, когда выполнено:

| Критерий | Описание | Статус |
|----------|----------|--------|
| **Стабильный runtime** | Нет крэшей в типовых сценариях, корректный shutdown | Частично |
| **Документированный API** | Публичные API с Doxygen, README модулей, гайд по сборке | Частично |
| **Тестирование** | Unit-тесты для core/ECS/physics, регрессия перед релизом | ECS + Physics (M1) |
| **Asset pipeline** | Импорт моделей/анимаций (glTF+), загрузка уровней, базовый стриминг | Частично |
| **Редактор** | Размещение объектов, иерархия, инспектор, Play/Stop, сохранение сцены | Есть |
| **Производительность** | LOD, frustum culling, профилирование, стресс-тест 1k+ объектов | Частично |
| **Аудио** | 3D-звук, музыка, эффекты (miniaudio/FMOD) | Базовый |
| **Скрипты** | Lua-геймплей, привязка к ECS | Есть |
| **Сетевое** | Опционально для первой игры; для коммерческого релиза — клиент-сервер, репликация | Нет |

### A.2. Текущее состояние (сводка)

- **Готово:** Core, ECS, Vulkan PBR, тени, post-process, физика (Bullet), частицы (CPU+GPU), hinge joints, редактор (hierarchy, properties, play, prefabs), Lua, скелетная анимация, сериализация сцен/префабов, базовая аудио (miniaudio).
- **Не хватает:** Unit-тесты, формальная документация API, LOD/стриминг ассетов, job system / многопоточность, сетевая подсистема, полный asset pipeline (Assimp, hot-reload).

## Часть B. Первая игра на движке

### B.1. Питч

**«Arena One»** — однопользовательская арена: физика, цели, волны противников, одна локация. Игрок двигается от камеры от первого/третьего лица, стреляет/толкает объекты, уничтожает ботов и достигает целей (уничтожить все волны / выжить N секунд). Демонстрирует рендер, физику, анимацию, скрипты, аудио и редактор.

### B.2. Core loop (30 сек)

1. **Действие** — игрок двигается (WASD), прицеливается (мышь), стреляет (ЛКМ) или толкает объекты (физика).
2. **Обратная связь** — попадания, разрушаемые объекты, звуки, частицы, боты реагируют.
3. **Награда** — враги падают, волна зачищена, открывается следующая волна или победа.
4. **Повтор** — следующий заход или следующая волна.

### B.3. Механики

- Управление: FPS-камера (уже есть), выстрел — raycast по клику, нанесение урона/импульса по RigidBody или по компоненту Health.
- Враги: AI на Lua или простой FSM (patrol → chase → attack), компонент Health, смерть → отключение/удаление или ragdoll (опционально).
- Цели: «Уничтожить всех», «Выжить 60 сек», одна арена, 3–5 волн.
- Окружение: арена (уже есть стены/пол в движке), боксы/препятствия с физикой, опционально — двери на hinge.

### B.4. Контент и объём

- 1 арена (одна сцена).
- 2–3 типа врагов (разный HP/поведение).
- 1 тип «игрока» (камера + оружие/импульс).
- UI: HUD (HP, волна, цель), экран победы/поражения (уже есть заготовки в GameSystem).
- Аудио: шаги, выстрел, попадание, фоновая музыка (1 трек), победа/поражение.

### B.5. Критерий готовности игры

- Запуск сцены «Arena One», 3–5 волн врагов, победа по условию «все уничтожены», поражение при HP ≤ 0.
- Сохранение/загрузка сцены из редактора, воспроизводимость без крэшей.

## Часть C. Этапы реализации (милестоуны)

### M1 — Фундамент качества (движок) ✅

1. **Тесты:** Google Test в CMake; тесты ECS (Registry, View, add/remove); тесты PhysicsSystem (create/remove rigid body, clear_all_bodies); заглушки для audio/particles в тестах.
2. **Документация:** README в корне (сборка, зависимости, запуск), docs/API.md с перечнем модулей и основных классов.
3. **Верификация:** `ctest --test-dir build -C Release` проходит (12 тестов).

### M2 — Игра: каркас и геймплей

1. **Игровой проект:** папка `game_arena_one/` или сцены/префабы в `assets/` для Arena One: сцена арены, префаб игрока, префаб врага.
2. **Компоненты/системы:** Health, Weapon/Shooter (raycast от камеры) — есть; EnemyAI (Lua enemy_chase.lua).
3. **Волны:** ✅ спавн по волнам: GameSystem (current_wave, waves_total, m_had_enemies_this_wave), Application::spawn_wave(wave_num), при очистке волны — спавн следующей; победа после зачистки всех волн.
4. **Верификация:** запуск сцены, волна 1 (3 врага), после зачистки — волна 2 (4 врага), … победа после волны 5.

### M3 — Контент и полировка игры

1. **Модели/анимации:** 1 модель врага (или куб с меткой), анимация «idle/walk» при наличии.
2. **Аудио:** звуки выстрела, попадания, победа/поражение, фоновая музыка (miniaudio).
3. **UI:** HUD (HP, волна), экраны победы/поражения (расширить текущий GameSystem).
4. **Верификация:** полный проход 3–5 волн, музыка и звуки, стабильность.

### M4 — Движок: asset pipeline и производительность

1. **Загрузка уровней:** явный контракт «уровень = сцена» (scene.json), загрузка по имени из главного меню или редактора.
2. **LOD/стриминг:** дистанционный LOD для мешей (переключение mesh по дистанции до камеры), без асинхронного стриминга на первом этапе.
3. **Профилирование:** замер FPS и времени систем (уже есть Profiler), стресс-тест 500–1000 боксов.
4. **Верификация:** смена уровня без перезапуска exe, FPS при 500 объектах приемлемый.

### M5 — Релиз движка и игры

1. **Документация:** обновить ARCHITECTURE.md, ROADMAP.md под финальное состояние; краткий гайд «Как собрать игру на Kenga».
2. **Релиз:** тег/архив с бинарником демо (Arena One) + README с требованиями и лицензией.
3. **Опционально:** CI (GitHub Actions) — сборка + тесты.

## Часть D. Порядок работ (приоритет)

1. **M1** — тесты и базовая документация (неделя).
2. **M2** — каркас игры Arena One и геймплей (1–2 недели).
3. **M3** — контент и полировка игры (1 неделя).
4. **M4** — asset pipeline и производительность движка (1–2 недели).
5. **M5** — финальная документация и релиз (неделя).

После M5 движок считается готовым к «коммерческому использованию для создания AAA-игр» в объёме, достаточном для инди/малой студии; одна игра (Arena One) — готова как демо и proof-of-concept.
